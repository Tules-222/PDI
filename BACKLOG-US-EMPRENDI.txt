BACKLOG DE USER STORIES — EMPRENDI
Revision del estado del sitio: 30/10/2026

OBJETIVO
Este documento conserva las 40 historias del texto original y las adapta al
producto y al codigo que existen en este repositorio. Sirve para crear issues
de GitHub, registrar como completado el trabajo existente y planificar el
trabajo pendiente.

ALCANCE DEL ANALISIS
- La aplicacion principal es el sitio Emprendi servido desde /public y
  construido desde /src.
- El repositorio tambien contiene /layered-architecture-main y /contacts.
  No se consideran funcionalidades de la aplicacion activa salvo que se
  integren expresamente.
- El sitio actual usa cuentas de usuario que tambien pueden vender. El perfil
  publico del vendedor y sus productos no son entidades independientes de
  "emprendimiento".
- "Hecha" significa que hay un flujo equivalente en el codigo inspeccionado;
  no reemplaza una prueba funcional completa ni una validacion visual.
- Las historias Parciales deben completarse antes de marcarlas como hechas.
- Las historias Pendientes requieren desarrollo.
- Las historias En decision no deben implementarse hasta cerrar el alcance
  indicado.

DECISIONES CONFIRMADAS PARA EL BACKLOG
- Multiples tiendas por cuenta: SI, implementar US-007 y adaptar productos,
  perfiles, permisos y pedidos.
- Administracion: conservar PIN compartido. La auditoria registra la sesion
  compartida, no una identidad personal.
- Recuperacion: dejar listo el envio SMTP por entorno y no simular entrega si
  faltan credenciales.
- Chat: base de datos y actualizacion periodica, sin tiempo real en la primera
  version.
- Ofertas: propuestas de vendedores con aprobacion administrativa antes de
  publicarse.
- Metricas: basarse en pedidos pagados/entregados; no inventar etiquetas de
  reputacion ni umbrales.
- US-006: cada emprendimiento permite logo, banner y colores principal/de
  acento propios.
- US-016: "mas vendidos" cuenta unidades de pedidos pagados y entregados
  creados durante los ultimos 90 dias.
- Soporte: canal configurable; no publicar contacto ficticio.

PRIORIDADES PENDIENTES
P0 — Seguridad y confiabilidad: completar la matriz de permisos y las pruebas
de acceso cruzado de US-040.
P1 — Experiencia base: validar SMTP real para US-003.
P2 — Definiciones de producto: acordar umbrales para US-029 antes de crear
etiquetas de reputacion.
Las prioridades son una propuesta de orden, no una confirmacion de requisitos.

GRUPO 1 — USUARIOS Y AUTENTICACION
======================================================================

US-001 — Registro de usuarios
ESTADO: HECHA
Como visitante, quiero crear una cuenta, para comprar productos y utilizar la
plataforma.
Alcance actual: el registro valida los campos, evita correos duplicados,
guarda la contrasena con hash y asigna el rol fijo de usuario.
Criterios de aceptacion:
- Con datos validos se crea la cuenta y se inicia la sesion.
- Con datos incompletos, correo invalido o ya registrado se informa el error y
  no se crea una cuenta duplicada.

US-002 — Inicio de sesion
ESTADO: HECHA
Como usuario registrado, quiero iniciar sesion, para acceder a las funciones
de mi cuenta.
Alcance actual: se verifican las credenciales y se rechazan cuentas
bloqueadas.
Criterios de aceptacion:
- Con credenciales correctas y cuenta activa se inicia sesion.
- Con credenciales incorrectas o cuenta no activa se rechaza el acceso sin
  revelar cual dato fue incorrecto.

US-003 — Recuperacion segura de contrasena
ESTADO: PARCIAL — PRUEBA DE ENVIO SMTP PENDIENTE
Como usuario que olvido su contrasena, quiero restablecerla usando mi correo
registrado, para recuperar el acceso a mi cuenta.
Criterios de aceptacion:
- El usuario puede solicitar instrucciones ingresando su correo.
- La respuesta no revela si ese correo esta registrado.
- El enlace de recuperacion es aleatorio, de un solo uso, expira y no cambia la
  contrasena si es invalido o vencio.
- Con un enlace valido se guarda una contrasena nueva con hash y se invalidan
  los enlaces anteriores.
Implementado: tokens aleatorios guardados como hash, de un solo uso y con una
hora de vigencia; envio por SMTP configurable, formulario CSRF y mensajes que
no revelan si el correo esta registrado. Sin configuracion SMTP, la pantalla
lo informa y no simula el envio. La migracion 015 debe aplicarse en cada base.
Pendiente: validar el envio y el restablecimiento de extremo a extremo con
credenciales SMTP reales.
DECISION CONFIRMADA: SMTP por entorno; no afirmar que se envio el correo si
faltan credenciales.

US-004 — Gestion de cuenta personal
ESTADO: HECHA
Como usuario, quiero consultar y modificar mis datos, para mantener actualizada
mi cuenta.
Alcance actual: cada usuario edita su propio perfil, datos de contacto y
presentacion comercial; puede cambiar su contrasena.
Criterios de aceptacion:
- Al guardar datos validos se actualiza la cuenta autenticada.
- Un usuario no puede leer ni modificar los datos privados de otra cuenta.

GRUPO 2 — EMPRENDIMIENTOS Y PERFIL COMERCIAL
======================================================================

US-005 — Perfil publico de vendedor
ESTADO: HECHA — PERFIL COMERCIAL PUBLICO
Como usuario vendedor, quiero completar y mostrar mi perfil comercial, para que
los compradores conozcan quien ofrece los productos.
Alcance actual: cada emprendimiento tiene un perfil publico con nombre,
ubicacion, descripcion y productos aprobados de esa tienda. Correo, direccion
y telefono privados no se exponen.
Criterios de aceptacion:
- El vendedor puede actualizar descripcion y ubicacion de cada emprendimiento
  propio.
- El perfil publico de cada emprendimiento muestra sus datos comerciales y
  unicamente sus productos aprobados.
- Los datos privados (correo, direccion y telefono) no se exponen en el perfil
  publico sin una decision explicita de producto.
Los datos visibles se limitan a nombre, ubicacion, descripcion y productos
aprobados; las tiendas y cuentas inactivas no se publican.

US-006 — Personalizacion del perfil comercial
ESTADO: HECHA — LOGO, BANNER Y PALETA DE COLORES
Como vendedor, quiero personalizar la presentacion de mi perfil, para
diferenciar mi negocio.
Alcance actual: cada tienda permite cargar o reemplazar un logo y un banner,
elegir un color principal y uno de acento, y quitar las imagenes. Los cambios
se aplican al perfil publico y a las tarjetas de busqueda.
Criterios de aceptacion:
- El vendedor puede personalizar por separado cada emprendimiento de su cuenta.
- Solo se aceptan imagenes JPEG, PNG o WebP; logo de al menos 100 x 100 y
  banner de al menos 640 x 180; maximo 5 MB por archivo y 40 megapixeles.
- La validacion del servidor comprueba contenido y MIME, no solo el nombre del
  archivo; entradas invalidas muestran un error y no sustituyen imagenes previas.
- Los colores se validan como hexadecimal de seis digitos y se muestran con
  contraste legible.
DECISION CONFIRMADA: logo, banner y colores principal/de acento. La migracion
020 agrega personalizacion por emprendimiento.
Validado por HTTP: guardar logo, banner y colores; rechazar un banner menor al
minimo sin reemplazar las imagenes previas; quitar el logo sin afectar el
banner; y rechazar con 404 la edicion desde otra cuenta.

US-007 — Administracion de multiples emprendimientos
ESTADO: HECHA — FLUJOS PRINCIPALES VALIDADOS
Historia original: Como usuario con varios emprendimientos, quiero
administrarlos desde una misma cuenta.
Alcance implementado: cada cuenta conserva la tienda inicial; puede crear,
editar y pausar otras tiendas. Los productos, perfiles publicos y snapshots de
compra se asocian a un emprendimiento.
Criterios si se confirma el alcance:
- El usuario puede crear, seleccionar, editar y administrar mas de una tienda.
- Cada tienda tiene perfil y catalogo separados.
- Las operaciones, ventas y permisos se limitan a la tienda seleccionada.
DECISION CONFIRMADA: permitir varias tiendas por cuenta como entidad propia,
propiedad de una cuenta. La migracion 014 crea una tienda inicial por cuenta
existente, conserva la titularidad y vincula productos e historial de pedidos.
Validado con sesion autenticada: creacion, edicion y pausa de una tienda
adicional; publicacion de un producto asociado a la tienda, confirmacion de
pedido y snapshot de tienda; una cuenta ajena recibe 404 al intentar editar
ese producto. La publicacion queda pendiente de moderacion antes de aparecer
en el catalogo.

US-008 — Administracion de productos propios
ESTADO: HECHA CON EL MODELO ACTUAL
Como vendedor, quiero administrar mis productos, para mantener actualizado mi
catalogo.
Alcance actual: cada usuario consulta, edita y elimina productos propios; los
cambios de contenido vuelven a revision y los pedidos conservan una copia de
los datos comerciales necesarios.
Criterios de aceptacion:
- El vendedor solo ve y modifica sus propias publicaciones desde "Mis
  productos".
- Las publicaciones aprobadas y sus cambios respetan el flujo de moderacion.
- El historial de compras conserva los datos del producto necesarios cuando
  este deja de estar disponible.

GRUPO 3 — PRODUCTOS
======================================================================

US-009 — Publicacion de productos
ESTADO: HECHA
Como vendedor, quiero publicar productos, para ofrecerlos a los compradores.
Alcance actual: se validan nombre, descripcion, precio, categoria, unidad,
compra minima, stock, confirmacion de producto real e imagenes; la publicacion
queda pendiente de revision.
Criterios de aceptacion:
- Una publicacion valida se guarda asociada a la cuenta y queda pendiente.
- Los datos invalidos impiden guardar y se explican al vendedor.
- Los productos pendientes o rechazados no aparecen como disponibles en el
  catalogo publico.

US-010 — Fotografia obligatoria
ESTADO: HECHA
Como vendedor, quiero agregar fotografias a mis productos, para mostrar sus
caracteristicas.
Alcance actual: se exige al menos una imagen valida; se admiten hasta cinco
imagenes JPEG, PNG o WebP con limite de tamano.
Criterios de aceptacion:
- Una imagen valida permite enviar la publicacion a revision.
- Sin imagen o con un archivo no permitido, no se puede publicar y se informa
  el motivo.

US-011 — Control de stock
ESTADO: HECHA
Como vendedor, quiero definir el stock de mis productos, para controlar su
disponibilidad.
Alcance actual: se valida stock entero y compra minima, se comprueba nuevamente
al confirmar el pedido y se descuenta dentro de una transaccion.
Criterios de aceptacion:
- No se puede agregar al carrito ni confirmar una cantidad superior al stock.
- No se puede comprar un producto sin stock confirmado o que no este aprobado.
- El stock se reserva/descuenta una sola vez cuando se confirma el pedido.

US-012 — Edicion de productos
ESTADO: HECHA
Como vendedor, quiero editar mis productos, para actualizar su informacion,
imagenes y stock.
Criterios de aceptacion:
- El vendedor puede modificar solo productos propios y los datos se validan.
- Un producto actualizado queda pendiente de una nueva revision antes de volver
  a aparecer como aprobado.
- Cada producto conserva al menos una imagen valida.

GRUPO 4 — BUSQUEDA, FILTROS Y OFERTAS
======================================================================

US-013 — Busqueda de productos
ESTADO: HECHA
Como visitante o comprador, quiero buscar productos por palabras clave, para
encontrar articulos de mi interes.
Criterios de aceptacion:
- La busqueda considera nombre, descripcion y categoria, unicamente en
  productos aprobados.
- Si no hay coincidencias, se informa y se permite modificar la busqueda.

US-014 — Busqueda de vendedores
ESTADO: HECHA COMO BUSQUEDA DE EMPRENDIMIENTOS
Como comprador, quiero buscar vendedores por su nombre o informacion
comercial, para encontrar sus perfiles y productos.
Criterios de aceptacion:
- La busqueda devuelve perfiles de vendedores que coinciden con el termino.
- Cada resultado lleva al perfil publico y muestra solo sus productos
  aprobados.
- Cuando no hay coincidencias, se informa sin exponer datos privados.
Alcance actual: la pagina /emprendimientos busca nombre, descripcion y
ubicacion de tiendas activas; cada resultado abre su perfil y catalogo.

US-015 — Filtros por categoria
ESTADO: HECHA
Como comprador, quiero filtrar productos por categoria, para encontrar
articulos especificos.
Criterios de aceptacion:
- Al elegir una categoria se muestran productos aprobados de esa categoria.
- La categoria se puede combinar con busqueda, orden y rango de precios.

US-016 — Ordenamiento de productos
ESTADO: HECHA — MAS VENDIDOS EN 90 DIAS
Como comprador, quiero ordenar los resultados, para comparar productos.
Alcance actual: el catalogo ofrece recientes, A-Z, menor precio, mayor precio
y mas vendidos.
Criterios de aceptacion:
- Cada criterio disponible devuelve resultados en el orden indicado.
- "Mas vendidos" ordena por cantidad de unidades en pedidos pagados y
  entregados dentro del periodo acordado; empates se resuelven de forma estable.
DECISION CONFIRMADA: contar unidades de pedidos con pago aprobado y estado
entregado, creados durante los ultimos 90 dias. Los productos sin ventas quedan
al final. Validado con datos temporales en una transaccion revertida: los
productos se ordenan por unidades y se excluyen compras antiguas, impagas o no
entregadas.

US-017 — Ofertas vigentes
ESTADO: HECHA — MIGRACION Y FLUJOS PRINCIPALES VALIDADOS
Como comprador, quiero consultar ofertas vigentes, para encontrar productos
promocionados y conocer su precio actual.
Alcance actual: migracion 018 aplicada en la base local. El vendedor propone
precio y vigencia; administracion aprueba o rechaza con motivo. Catalogo,
detalle, favoritos, carrito y checkout calculan el precio vigente; el pedido
conserva el precio aplicado como snapshot. Las fechas se interpretan en
APP_TIMEZONE y se guardan/comparan en UTC para evitar diferencias entre PHP y
MySQL. El vendedor puede desactivar una oferta y las ofertas vencidas dejan de
aplicarse.
Criterios de aceptacion:
- Una oferta activa muestra precio original, precio promocional y vigencia.
- Una oferta vencida o desactivada deja de mostrarse como vigente y no cambia
  el precio cobrado.
- El precio y las fechas se validan en el servidor al agregar y confirmar el
  pedido.
DECISION CONFIRMADA: el vendedor propone un precio menor al regular y fechas de
vigencia; la oferta solo se muestra despues de aprobacion administrativa. No se
inventan descuentos minimos/maximos. Validado de extremo a extremo: propuesta,
aprobacion, rechazo con motivo, aplicacion del precio en checkout, snapshot de
compra y reserva de stock; tambien se probaron ofertas vencidas/no aprobadas.
Aplicar la migracion 018 en cada entorno adicional al desplegar.

GRUPO 5 — CARRITO Y COMPRAS
======================================================================

US-018 — Agregar productos al carrito
ESTADO: HECHA
Como comprador, quiero agregar productos al carrito, para reunir los articulos
que deseo comprar.
Criterios de aceptacion:
- Solo se agrega un producto aprobado, con stock suficiente y respetando la
  cantidad minima.
- No se permite comprar publicaciones propias.
- Se vuelve a validar el stock al confirmar el pedido.

US-019 — Modificar el carrito
ESTADO: HECHA
Como comprador, quiero modificar o quitar productos del carrito, para ajustar
mi seleccion.
Criterios de aceptacion:
- Al actualizar la cantidad, se validan stock y minimo de compra.
- Al quitar un articulo, se elimina del carrito propio.
- Los importes se recalculan con los precios vigentes mostrados por el sitio.

US-020 — Consultar el carrito con detalle visual
ESTADO: HECHA
Como comprador, quiero revisar el contenido de mi carrito, para verificar mi
compra antes de continuar.
Alcance actual: cada linea incluye la imagen del producto o un marcador visual
si no hay imagen.
Criterios de aceptacion:
- Cada linea muestra imagen, producto, cantidad, precio unitario y subtotal.
- El resumen muestra el total de productos y el importe actualizado.
- Un carrito vacio presenta un mensaje y un enlace al catalogo.
- Los articulos no disponibles se identifican y no permiten confirmar el
  pedido.

GRUPO 6 — CHAT Y COMUNICACION
======================================================================

US-021 — Chat entre comprador y vendedor
ESTADO: HECHA
Como comprador, quiero conversar con un vendedor, para consultar sobre sus
productos.
Criterios de aceptacion:
- Un comprador puede iniciar una conversacion asociada a un vendedor y,
  opcionalmente, a un producto.
- Los participantes pueden enviar mensajes y consultar el historial propio.
- Ningun otro usuario puede consultar o enviar mensajes a esa conversacion.
- Los mensajes se almacenan de forma persistente y se validan en el servidor.
DECISION CONFIRMADA: chat persistente en base de datos con actualizacion
periodica; no se requiere WebSocket en la primera version.
Alcance actual: inicio desde perfiles de emprendimiento o productos, envio e
historial persistentes, consulta periodica cada 5 segundos y control de
participantes.

US-022 — Administracion de conversaciones
ESTADO: HECHA
Como vendedor, quiero organizar y responder las conversaciones de mis
compradores, para atender sus consultas.
Criterios de aceptacion:
- El vendedor ve conversaciones de las que es participante y puede responder.
- Las conversaciones permiten distinguir mensajes nuevos de los ya leidos.
- No se muestran conversaciones ni datos de otros vendedores.
Dependencia: US-021.
Alcance actual: comprador y vendedor ven solo sus conversaciones; la bandeja
muestra mensajes sin leer y protege las rutas por participante.

US-023 — Diseno responsivo
ESTADO: HECHA — VALIDACION VISUAL Y RESPONSIVE
Como usuario, quiero que la plataforma se adapte a distintos dispositivos,

Alcance actual: hay estilos responsivos para anchos de pantalla reducidos.
Criterios de aceptacion:

Validado con navegador en 375, 768, 860 y 1440 px para portada, detalle,

detecta desbordamiento horizontal; el menu movil se abre y muestra sus enlaces.

US-024 — Navegacion movil compacta
ESTADO: HECHA
Como usuario, quiero una navegacion compacta en pantallas pequenas, para

Alcance actual: la navegacion movil tiene un menu desplegable general, separado

Criterios de aceptacion:
- En pantalla pequena existe un control claro para abrir y cerrar la

- Las opciones se muestran segun la sesion y las funciones disponibles.

US-025 — Accesos a secciones personales
ESTADO: HECHA CON AJUSTE DE NOMENCLATURA
Como usuario autenticado, quiero acceder a mis productos, ventas, compras,

Alcance actual: el menu de cuenta contiene esos accesos; la opcion se llama
"Mi perfil" y las ventas/productos pertenecen a la cuenta vendedora.
Criterios de aceptacion:
- Las opciones personales solo aparecen para usuarios autenticados.
- Las rutas protegidas verifican la sesion y la propiedad de los recursos.
- El menu permite acceder a los emprendimientos propios y sus publicaciones.

US-026 — Retiro de Overshine Contacts
ESTADO: HECHA
Como usuario, quiero que se retiren los accesos a Overshine Contacts, para

Alcance actual: no se encontraron referencias activas a Contacts en la

Criterios de aceptacion:
- La aplicacion activa no muestra enlaces, textos ni componentes de Overshine

- La eliminacion de una referencia no rompe otra funcionalidad de Emprendi.
- La frase original "el chat continua disponible" solo se podra aceptar cuando
  US-021 y US-022 esten implementadas.
Actualizacion: el chat propio de Emprendi esta implementado y no depende del
directorio Contacts.

GRUPO 9 — REPUTACION Y RENDIMIENTO COMERCIAL
======================================================================

US-029 — Indicadores de reputacion del vendedor
ESTADO: PENDIENTE — CRITERIOS POR DEFINIR
Como comprador, quiero ver indicadores de reputacion del vendedor, para contar
con mas informacion al elegir.
Alcance actual: se muestran opiniones verificadas del vendedor; no hay
etiquetas por volumen de ventas o trayectoria.
Criterios de aceptacion:
- Las etiquetas se basan en reglas publicadas y calculables a partir de datos
  verificables.
- Solo cuentan pedidos que alcanzaron el estado de finalizacion definido.
- El perfil explica el significado de cada etiqueta y no promete garantias.
DECISION CONFIRMADA: para metricas comerciales contar pedidos pagados y
entregados segun cada metrica; no crear etiquetas de reputacion hasta que se
definan umbrales de ventas, antiguedad y calificacion.

US-030 — Opiniones verificadas de productos y vendedores
ESTADO: HECHA CON ALCANCE ACTUAL
Como comprador, quiero dejar una opinion despues de recibir un producto, para
compartir mi experiencia de compra.
Alcance actual: se permite una opinion por articulo de un pedido entregado;
incluye puntuacion y comentario, y se muestra el promedio en el producto y el
perfil del vendedor. No es una calificacion independiente de un emprendimiento.
Criterios de aceptacion:
- Solo el comprador de un pedido entregado puede opinar sobre el articulo.
- No se permite duplicar una opinion para el mismo articulo del pedido.
- La puntuacion y el comentario se validan y el promedio se actualiza a partir
  de opiniones verificadas.

US-031 — Panel de rendimiento del vendedor
ESTADO: HECHA — TOTALES HISTORICOS
Como vendedor, quiero consultar las estadisticas de mis ventas y productos,
para conocer el rendimiento de mi cuenta.
Criterios de aceptacion:
- El panel presenta metricas con periodo y definiciones comprensibles.
- Los resultados incluyen unicamente datos de la cuenta autenticada.
- Se definen con precision estados de compra y formulas antes de presentar
  importes como ingresos o ventas completadas.
Alcance actual: muestra pedidos y unidades pagados, pedidos entregados,
importe bruto de productos pagados (sin envio), productos aprobados visibles
y seguidores unicos. El periodo es todo el historial; solo cuenta
estado_pago=aprobado y entrega con estado=entregado.
DECISION CONFIRMADA: no inventar etiquetas ni umbrales de reputacion.

US-032 — Seguir vendedores
ESTADO: HECHA COMO SEGUIMIENTO DE EMPRENDIMIENTOS
Como comprador, quiero seguir o dejar de seguir vendedores, para encontrar
facilmente los perfiles que me interesan.
Criterios de aceptacion:
- Un usuario autenticado puede seguir y dejar de seguir un perfil de vendedor.
- La relacion no se duplica y el contador coincide con los seguidores reales.
- Los vendedores no pueden manipular el contador mediante solicitudes
  directas.
Alcance actual: la relacion unica es por cuenta y emprendimiento; se puede
seguir, dejar de seguir y consultar la lista propia. El panel cuenta seguidores
unicos a traves de todas las tiendas de la cuenta.

US-033 — Acceso al panel administrativo
ESTADO: HECHA — PIN COMPARTIDO Y CSRF
Como administrador, quiero acceder al panel protegido por el PIN
administrativo, para supervisar la plataforma.
Alcance actual: el panel utiliza un PIN compartido configurado en el entorno;
no hay rol administrativo individual de usuario.
Criterios de aceptacion:
- Solo quien conoce el PIN configurado puede acceder a operaciones del panel.
- Las operaciones administrativas comprueban la sesion de administracion en
  el servidor y protegen formularios contra CSRF.
- Las acciones quedan registradas como realizadas mediante el PIN compartido;
  no se debe atribuir una identidad individual que el sistema no conoce.
DECISION CONFIRMADA: conservar el PIN compartido. Se documentara la limitacion
de auditoria; no se afirmara que el registro identifica a una persona concreta.
Validado: inicio de sesion administrativa, consulta protegida de auditoria y
redireccion de una sesion no autorizada. Las rutas administrativas de cambio
comprueban la sesion y el token CSRF.

US-034 — Gestion de reportes e irregularidades
ESTADO: HECHA — REPORTES DE PRODUCTOS Y CUENTAS
Como administrador, quiero revisar reportes pendientes de publicaciones, para
investigar incumplimientos.
Alcance actual: compradores pueden reportar productos y cuentas; el panel
permite revisar y descartar reportes, retirar publicaciones o bloquear cuentas.
La migracion 019 crea la cola de reportes de cuentas.
Criterios de aceptacion:
- El panel muestra cada reporte pendiente, motivo, detalle y fecha.
- El administrador puede descartar el reporte o tomar una medida disponible.
- La decision actualiza el estado del reporte y registra la accion.
- Cuando no hay casos pendientes, se informa claramente.
Alcance inicial propuesto: reportes de productos y cuentas de usuario. Los
emprendimientos separados no aplican salvo que se apruebe US-007.
Validado: la cola muestra y resuelve un reporte de cuenta; el bloqueo, el
estado del reporte y el evento de auditoria se guardan juntos.

US-035 — Moderacion de productos
ESTADO: HECHA — DECISIONES AUDITADAS
Como administrador, quiero aprobar, rechazar o retirar productos, para
mantener un catalogo confiable.
Alcance actual: se pueden aprobar o rechazar publicaciones pendientes con
motivo; tambien retirar publicaciones mediante gestion de reportes.
Criterios de aceptacion:
- Una publicacion pendiente puede aprobarse o rechazarse con un cambio de
  estado valido.
- Una publicacion aprobada puede retirarse y deja de estar disponible para
  compradores.
- Las decisiones y sus motivos quedan registradas con actor y fecha.
- Solo administradores autorizados pueden ejecutar estas operaciones.
Las aprobaciones, rechazos y retiros por reporte registran accion, entidad,
actor y fecha; el rechazo y el retiro requieren motivo. Solo se cambian
publicaciones en estados compatibles con la decision.

US-036 — Moderacion de cuentas de usuario
ESTADO: HECHA — MOTIVOS, AUDITORIA Y ANONIMIZACION
Como administrador, quiero moderar cuentas de usuarios vendedores, para
intervenir ante incumplimientos.
Alcance actual: el panel permite editar, bloquear, desbloquear y anonimizar/
eliminar una cuenta; no gestiona emprendimientos independientes.
Criterios de aceptacion:
- Un administrador autorizado puede bloquear y reactivar una cuenta.
- Una cuenta bloqueada no puede iniciar sesion ni realizar operaciones.
- La eliminacion protege el historial comercial y elimina o anonimiza los
  datos personales segun la politica definida.
- Las medidas, el motivo, el actor y la fecha quedan registrados.
Bloquear, reactivar y eliminar requiere un motivo de 10 a 500 caracteres y
registra la accion atomicamente. Las cuentas bloqueadas no pueden iniciar
sesion y las sesiones existentes pierden acceso. Al eliminar se anonimiza el
perfil, se retiran productos, se desactivan tiendas y se conservan pedidos y
articulos historicos. Validado con cuenta de prueba temporal.

US-037 — Acceso administrativo auditado a conversaciones
ESTADO: HECHA CON ACCESO AUDITADO
Como administrador expresamente autorizado, quiero consultar una conversacion
por un motivo justificado, para investigar un reporte.
Criterios de aceptacion:
- El acceso requiere permiso y motivo asociado a un caso concreto.
- Se registra administrador, conversacion, motivo y fecha de acceso.
- Los accesos y mensajes no se exponen a otros usuarios.
DECISION CONFIRMADA: el administrador puede ver contenido solo despues de
indicar un motivo de al menos 20 caracteres. El listado administrativo no
muestra mensajes; cada acceso requiere sesion PIN, queda auditado con motivo y
huella de sesion, y habilita una sola consulta. La auditoria atribuye la accion
al PIN compartido, no a una persona concreta.

US-038 — Consulta administrativa del historial de compras
ESTADO: HECHA — FLUJO Y AUDITORIA VALIDADOS
Como administrador autorizado, quiero consultar compras y sus estados, para
investigar operaciones y ayudar a resolver reclamos.
Alcance actual: consulta administrativa por identificador con motivo de al
menos 20 caracteres, auditoria antes de mostrar los datos y datos limitados a
la compra y sus articulos. Validado con sesion administrativa: consulta exitosa
y registro en auditoria; la ruta sin autenticacion redirige al acceso
administrativo.
Criterios de aceptacion:
- El administrador autorizado puede localizar una compra y consultar estados,
  articulos, pago y envio necesarios para una investigacion.
- La consulta administrativa no permite modificar el historial comercial.
- Los datos personales se limitan a lo necesario y el acceso queda auditado.
- Los usuarios sin permiso reciben acceso denegado.

US-039 — Historial de actividad administrativa y comercial
ESTADO: HECHA — CONSULTA FILTRABLE
Como administrador autorizado, quiero consultar acciones relevantes, para
auditar cambios y reconstruir lo ocurrido.
Alcance actual: se registran acciones comerciales, moderacion, reportes,
consultas administrativas de compras/conversaciones y cambios de cuenta.
`/admin/auditoria` permite filtrar por fechas, actor, entidad y accion y muestra
hasta 200 resultados. Los usuarios se identifican como `usuario:ID`; el PIN
administrativo queda identificado como compartido.
Criterios de aceptacion:
- Se registran acciones relevantes con actor, fecha, entidad, identificador y
  detalle no sensible.
- Un administrador autorizado puede filtrar el historial por fecha, actor,
  entidad y accion.
- Los registros no se pueden alterar desde funciones ordinarias del sitio.
- No se guardan contrasenas, tokens ni secretos en el historial.
Validado el acceso protegido, los filtros y el registro de cambios de estado,
eliminacion y moderacion. No se guardan contrasenas, tokens ni credenciales.

US-040 — Control de permisos y propiedad de recursos
ESTADO: PARCIAL — P0
Como responsable de la plataforma, quiero validar permisos en el servidor en
cada operacion protegida, para impedir accesos no autorizados.
Alcance actual: existen sesiones, tokens CSRF en formularios y controles de
propiedad en varios flujos; las funciones administrativas usan PIN compartido.
Criterios de aceptacion:
- Cada ruta protegida verifica sesion, rol y propiedad del recurso en el
  servidor; ocultar un boton no se considera control de acceso.
- Un usuario no puede leer, editar o eliminar datos de otra cuenta manipulando
  identificadores.
- Las operaciones que cambian estado requieren metodo y proteccion CSRF
  adecuados.
- Los fallos de permisos se rechazan sin revelar datos privados y se registran
  cuando son relevantes para seguridad.
Trabajo pendiente: terminar la matriz de permisos y probar intentos de acceso
cruzado en todas las rutas protegidas.
DECISION CONFIRMADA: se conserva el PIN administrativo compartido; no se
implementaran cuentas administrativas individuales sin una nueva decision.
